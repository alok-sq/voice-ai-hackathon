# Dark Mode ("Night sky") Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a navy "Night sky" dark theme to the console. It follows the OS setting by default, and a top-bar button overrides it; the light theme stays pixel-identical.

**Architecture:** `<html data-theme>` is the only switch. Under `:root[data-theme="dark"]`, `tokens.css` re-values the raw scales (ink becomes navy neutrals, hue tints become low-alpha, hue text steps become light), so the semantic tokens follow automatically. A few literal-colour spots get dark overrides in `app.css`. An inline script in `index.html` sets the theme before first paint; the `useTheme` hook keeps it in sync and saves the choice.

**Tech Stack:** React 19, Vite 7, TypeScript 5.9, plain CSS custom properties, Vitest (node env), Playwright (from the npx cache) for screenshots.

**Spec:** `docs/superpowers/specs/2026-11-26-dark-mode-design.md`

## Global Constraints

- The light theme must not change: no light-mode value changes, and any light-mode CSS edit must resolve to the identical colour.
- Storage key `console.theme`, values `"light"` / `"dark"`; no key means follow the system setting.
- Contrast in dark: body text ≥ 4.5:1, hints and captions ≥ 3:1.
- These do not change in dark: brand mid-steps `-300`…`-500`, deep steps `-800`…`-950` of blue/sun/leaf/rust, and `--grid-500`.
- `web/` only. Commits carry no AI attribution lines. Work on `feature/RMX-241-ui-integration`; the user pushes.

## Review Focus

1. **Dark fills with white text** (`.btn--primary`, `.tab__count`, which use `--ink-900` as a background): must stay readable in dark. Covered by the Task 2 rule change and the Task 4 screenshot.
2. **Storage blocked or holding junk** (private window, `console.theme = "blue"`): the console follows the system setting and never throws. Covered by Task 1 tests and the try/catch in both the inline script and the hook.
3. **OS theme changes while the console is open with no saved choice**: it switches live. With a saved choice, it ignores the OS. Covered by the Task 1 hook and checked by hand in Task 4.
4. **Intro dialog opens on every load**: its sunrise wash and backdrop must read correctly in dark from the very first frame, with no flash. Covered by the Task 4 screenshots.
5. **Saved sessions and the summary card** use tint-plus-strong-text chips: they must stay legible in dark. Covered by the Task 4 history and session screenshots.

### Task 1: Theme state and no-flash boot

**Files:**
- Create: `web/src/state/theme.ts`, `web/src/state/theme.test.ts`, `web/src/state/useTheme.ts`
- Modify: `web/index.html` (inline script in `<head>`, before the stylesheet link)

**Interfaces (produces):**
- `export type Theme = "light" | "dark"`
- `export const THEME_KEY = "console.theme"`
- `export function parseTheme(raw: string | null): Theme | null`: only the exact strings `"light"` and `"dark"` are accepted.
- `export function resolveTheme(saved: Theme | null, systemDark: boolean): Theme`
- `export function useTheme(): [Theme, (next: Theme) => void]` (in `useTheme.ts`). It:
  - sets `document.documentElement.dataset.theme`;
  - listens to `matchMedia("(prefers-color-scheme: dark)")` changes only while nothing is saved;
  - saves the choice with try/catch, like `useSoundPreference`.

- [ ] **Step 1: Write the failing tests** in `theme.test.ts`:

```ts
it("a saved choice beats the system", () => {
  expect(resolveTheme("light", true)).toBe("light");
  expect(resolveTheme("dark", false)).toBe("dark");
});
it("no saved choice follows the system", () => {
  expect(resolveTheme(null, true)).toBe("dark");
  expect(resolveTheme(null, false)).toBe("light");
});
it("ignores anything stored that is not a theme", () => {
  expect(parseTheme(null)).toBeNull();
  expect(parseTheme("blue")).toBeNull();
  expect(parseTheme("Dark")).toBeNull();
  expect(parseTheme("dark")).toBe("dark");
});
```

- [ ] **Step 2:** Run `npx vitest run src/state/theme.test.ts`. Expected: FAIL (module not found).
- [ ] **Step 3:** Implement `theme.ts`, then `useTheme.ts`. Read the initial state from `document.documentElement.dataset.theme` so it matches what the inline script already set.
- [ ] **Step 4:** Add the inline script to `index.html`. It does `try { parse localStorage[console.theme] } catch {}`, falls back to `matchMedia`, and sets `document.documentElement.dataset.theme`. The values are inlined because it runs before any module loads.
